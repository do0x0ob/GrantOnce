# GrantOnce 演示腳本（3–5 分鐘）

事前：`npm run dev`，開 **http://localhost:43127**（不要用 127.0.0.1，WebAuthn 不收 IP），右上「重設」。
Chrome 建議。若認證器不支援 PRF，用「改用軟體金鑰」，流程一模一樣。

上台前跑一次 `npm run test:rehearsal`——它會逐句驗證下面每一段講稿。跑完按「重設」。

頂欄是「授權 | 金庫 | 機關 | 憑證 | 登記台」。主路都在授權與機關。

---

## 0. 一句話開場（15 秒）

> 主辦方說跨部門互通卡在法規不是技術：公務機關只能在執行法定職務必要範圍內蒐集個資。
> 所以我們沒有繞過法規，我們把法規變成程式碼會檢查的條件。
> 一次資料流動要兩把鑰匙：**你的簽章**，加上**機關的法定職務**。

## 1. 建立簽章金鑰（20 秒）

點「用 passkey 建立」→ Face ID。PRF 不支援就點「改用軟體金鑰」。

> 金鑰是 passkey 的 PRF 派生出來的。私鑰不儲存，每次簽都重新算、算完即丟，伺服器只有公鑰。

## 2. 說一句話：只給名單，不鑄匣（25 秒）

點「演示這句：我剛搬家，看我能申請什麼。」

> 資格由規則引擎決定，模型不決定授權。
> 畫面只出**符合的已登記服務名單**。沒有匣、沒有服務需求紀錄——只是問問，不會替任何服務留下痕跡。

## 2a. 選一項：機關才回「這次要什麼」（20 秒）

點名單上的「育兒津貼」。

> 選了，才向社會局提出辦理申請。它依登記規格回覆**本次必要資料**。
> 這還不是授權。卡片寫得很清楚：現在還沒有任何可簽署的匣。

## 2b. 確認需求：這時才做法源檢查、才鑄匣（25 秒）

點「確認『育兒津貼』的資料需求」。

> 確認之後，系統才檢查：目的在登記表內、個資依據成立。通過了才鑄出匣。
> 先問「這個人要不要辦」，才問「這個機關有沒有權力要」。反過來做，等於替沒人開口要的服務先鑄好授權。

再點名單上的「住宅冷氣汰換補助」，同樣確認一次。兩張匣這時才出現。

> 為什麼兩張都要：下一段「拿乙的匣來兌現」要示範受眾不符。乙沒簽的話，畫面會顯示尚未簽署，講的跟看到的就對不上。

## 3. 這裡是重點：匣裡沒有個資（40 秒）

指著育兒津貼那張卡。

> 社會局會收到四件事：**是否**設籍新北市、**是否**一年內遷入、**是否**為法定親子關係，以及幼兒年齡帶——注意卡片上寫的是可選的三格「0-2／2-5／5+」，實際落在哪一格，要等兌現後才在機關欄看到。
>
> 就這樣。姓名、地址、戶號、出生日期，一個都不用給。核定育兒津貼本來就只需要知道這四件事。

指著冷氣補助那張。

> 這裡更有意思：經濟部拿到的是用電**級距**，加上一個**只屬於經濟部的帳戶代號**。
> 不是電號。所以就算經濟部和社會局私下交換資料庫，也拼不回同一個人。

## 4. 看我簽的是什麼（30 秒）

點「看我簽的是什麼」。

> WebAuthn 的系統彈窗不會顯示你在簽什麼——這是盲簽問題，我們正面處理：
> 把畫面上這段文字本身也簽進去。事後才證明得了「當時看到的就是這段」。
>
> 簽章還涵蓋：請求機關、資料來源、告知事項、只有社會局能兌現、綁定社會局的公鑰指紋、一次性編號、十分鐘後過期。

## 5. 簽署與兌現（35 秒）

兩張都點「簽署並授權來源機關交付」，然後頂欄切「機關」，甲點「持 Grant 向資料來源機關取證」，接著點「使用收到的證明開始處理」。

> 兩把鑰匙都轉了。收件匣出現四個述詞，每一個都帶著來源機關的簽章，機關可以自己驗。
> 年齡帶到這裡才看得到值：**0-2**。
> 中間欄的金庫：被用到的欄位標成「已派生述詞」——欄位本身沒有離開。所得永遠是「永不授權」。

## 6. 攻擊三連（45 秒）

同一張機關卡，展開「試著越界」，依序點：

**「拿『經濟部』的匣來兌現」**（乙必須已簽署、尚未兌現）
> 受眾不符。匣綁死了機關，撿到也沒用——它不是 bearer token。
> 綁定是簽章的一部分：`cnf.jkt` 就在委託人簽的那串 bytes 裡，改不了。

**「重放已兌現的匣」**
> 一次性編號已經燒掉了。

**「索取所得與地址」**
> 這個最重要。看左欄——代理人**主動推播**攔截通知，理由有三條：
> 不在育兒津貼的法定職務必要範圍（個資法 §15）、屬特種個資、超過委託上限。
>
> 注意攔截發生在**提案階段**。委託人根本沒有機會按下同意。
> 就算他被釣魚簽了，第二把鑰匙照樣不轉——因為社會局辦育兒津貼沒有蒐集所得的法源。

## 6b. 順帶（如果評審追問「怎麼證明綁定真的被簽了」）

點「看我簽的是什麼」，再展開「待簽的原始 bytes」。

> `cnf.jkt` 就在這串 bytes 裡。這不是設定檔上的一行，是簽章涵蓋的內容。
> 而且兌現前我們會把 body 重新序列化跟這串比對——不然改 body 不改簽章就過關了，簽章等於裝飾。

## 7. 出生證明那 3–5 天（25 秒）

頂欄「憑證」，或金庫裡的皮夾憑證。

> 親子關係憑證效期一年，由戶政簽發一次。
> 出生證明要調 3–5 個工作天——這裡只付一次，之後每個申請都出示同一張，不再調閱。
> 這就是把 MyData 和數位憑證串起來：MyData 是取得的管道，皮夾是出示的方式。
> 憑證頁可以把同一張 SD-JWT 出示四題或兩題——少給是長度差，不是口號。

## 8. 動態授權（25 秒）

頂欄「金庫」，點「+13 個月」。

> 幼兒滿 2 歲，代理人主動推送資格變更。育兒津貼不再成立。
> 原本簽過的匣**不會自動沿用**——條件變了就要重新確認、重新簽一張，新的編號、新的效期、新的簽章。
> 時鐘自己打開「未滿 5 歲幼兒托育補助」的需求，**不會替你鑄匣**。鑄匣還是要你確認。

## 8b. 但它不是只會報壞消息（25 秒）

同一輪推播有兩則，指第二則（綠色那張）。

> 同一次巡檢，代理人還說了另一件事：**你現在符合「未滿 5 歲幼兒托育補助」**。
> 這才是主動代理人真正的價值——它替你發現你不知道自己有的資格。
> 而且新的需求只要三個述詞，比育兒津貼還少一項：連「一年內遷入」都不需要。
>
> 每則推播下面那行「建議的下一步」是給代理人看的。
> 注意它永遠不會是「簽署」——工具清單裡根本沒有簽署工具，所以那條路不存在。

按其中一則的「簽收」。

> 簽收只表示看過了，不會授權任何事。稽核會多一筆。

## 8c. 它是真的一直在看（20 秒）

指標題列的「代理人上次巡檢：hh:mm:ss」。

> 這不是網頁在你按下按鈕時才算一次。MCP server 每 15 秒自己跑一輪巡檢。
> 開著 `npm run mcp` 什麼都不做，十五秒後 `get_notifications` 自己就長出東西了。
>
> 推播寫兩份：給你看的那份可以寫「離開 0-2 年齡帶」，那本來就是關於你的事實；
> 給模型看的那份只寫「已離開適用範圍」。模型全程拿不到述詞的值，有測試在守這條線。

## 9. 撤銷，誠實版（30 秒）

左欄「停止委託」。

> 撤銷要拆成三件事講：
> 停掉委託——**做得到**，立刻，未兌現的匣全部作廢。
> 撤銷還沒兌現的匣——**做得到**，短效加一次性編號。
> 已經交給機關的東西——**收不回來**。
>
> 第三項我們不裝作做得到。所以唯一的防線是一開始就少給。
> 育兒津貼那四個述詞就算收不回來也無所謂，它本來就不含個資。

## 9b. 如果被打斷超過十分鐘

匣的效期是 600 秒。過期的卡片會變紅並說明，簽署按鈕會停用。

> 這正是短效授權該有的行為。重新走三拍就會產生一張新的匣，新的編號、新的效期。

## 10. 收尾（20 秒）

> 稽核軌跡在機關頁下方：設定、發證、簽署、兌現、送件、撤銷、拒絕、推送、簽收，每一筆都有。
>
> 這不是又一個授權 demo。它在回答主辦方說的那句「根源是法規而非技術」——
> 把個資法 §15 的法定職務範圍寫成一張機器可讀的表，讓它每次兌現都被檢查一遍。

## 彩排

腳本的每一句都有對應的斷言：

```bash
npm run dev
npm run test:rehearsal
```

它會抓到「講的跟畫面顯示的對不上」這種錯——事實上上面幾處措辭就是它抓出來改的。
跑完會自動把狀態重設，但保險起見再按一次右上「重設」。

## 完整 E2E（上台前自動化）

主路必須跟上面講稿同一條，不能另寫一套：

1. 軟體／passkey 金鑰登記
2. 探索：只出名單，`serviceRequests === 0`、`grants === 0`
3. 選育兒 → 一筆 `awaiting-confirmation`，仍無匣
4. 確認需求 → 法源檢查通過 → 鑄 `G-甲`
5. 選冷氣並確認 → 鑄 `G-乙`
6. 兩張都簽；甲兌現、送件；收件匣四個述詞、無金庫值
7. 攻擊：`WRONG_AUDIENCE`、`REPLAYED`、索取所得被提案攔截並推播
8. 皮夾親子關係憑證效期一年；兩個月後再辦少要一項
9. 金庫 +13 個月：育兒資格掉、托育需求打開、**不鑄匣**
10. 停止委託：未兌現作廢，已交付留在機關
11. 稽核含 register / issue / sign / redeem / submit / revoke / deny / notify / acknowledge

```bash
npm run test:all          # sdjwt + flow + mcp + agent + docs + race + rehearsal
npm run test:mutate       # 注入的 bug 都必須被上面某套抓住
```
