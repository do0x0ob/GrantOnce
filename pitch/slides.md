# GrantOnce 簡報大綱

只放 README 沒有的東西：講稿骨架與口白。細節查 README。

## 1｜開場一句
兩把鑰匙才開得了：你的簽章，加上機關的法定職務。

## 2｜先講痛點，用主辦方自己的話
「技術上直接串起來最好，但因為法規沒辦法直接串聯。」
→ 所以我們不繞過法規，我們把法規變成程式每次兌現都會檢查的條件。

## 3｜押這句（主辦方原話）
「重點不是你有沒有憑證，而是**驗證方有沒有權力驗證**。」
這就是第二把鑰匙。整場圍繞它講。

## 4｜示範，不要解釋
打開育兒津貼那張卡：四個是非題與一個年齡帶。
停三秒，讓評審自己發現姓名地址戶號生日都不在上面。

## 5｜最強的一刀
「核定育兒津貼本來就只需要知道這四件事。所以我們不給第五件。」

## 6｜攻擊三連（現場點）
拿別人的匣 → 受眾不符。重放 → 編號燒掉了。索取所得 → 提案階段就攔截。
第三個要指左欄：代理人**主動**推播，理由三條，委託人根本沒機會按同意。

## 7｜跨機關串接
甲和乙拿到不同代號。「兩個機關交換資料庫也拼不回同一個人。」

## 8｜出生證明
「調一次要 3–5 個工作天。我們只付一次，之後每個申請都出示同一張。」
這是 MyData 與數位憑證串起來的具體樣子。

## 9｜誠實的一頁（評審會記得這個）
已交付的資料收不回來。我們不假裝做得到。
所以唯一的防線是一開始就少給——那四個述詞收不回來也無所謂。

## 10｜為什麼你們該相信這不是投影片工程
`npm run test:mutate`：我們往程式裡注入 22 個 bug，每一個都必須讓某個測試變紅。
現場可以跑給你看。

## 11｜路線圖與邊界
機關私鑰要移出伺服器（GCA 機關憑證／mTLS）；正式版簽章走 TW FidO；
交付後的使用只能靠稽核與最小揭露，不能靠技術強制。

## 收尾
「這不是又一個授權 demo。它在回答主辦方說的那句『根源是法規而非技術』。」
